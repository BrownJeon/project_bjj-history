## 1. 화면 개요

진입 경로는 기존 기술 탭 → 기술트리 → 기존 기술 카드다. 목록 검색·즐겨찾기·최신순·페이지네이션과 포지션/태그 관리 흐름은 유지한다. 기존 ID·이름·개인 메모·연습/성공·영상 연결을 보존한다. 니컷과 니슬라이드는 별도 항목으로 유지한다.

설명은 개인 메모와 다른 읽기 정보다. 메모 입력값을 설명으로 덮어쓰거나 공통 설명을 개인 메모에 합치지 않는다. 챔피언 화면은 이번 구현 대상이 아니며 백데이터 검토와 별도로 취급한다.

각 관계 행은 기술명과 조건/관계 설명을 가진 기존 시안 카드 모양을 반복한다. 행 높이는 최소 56px, 새 버튼·summary는 최소 44px. 관계명·조건은 줄바꿈으로 모두 읽을 수 있게 하며 의미를 말줄임으로 숨기지 않는다. 조건은 짧은 한 문장으로 제공하되 좁은 폭에서 2줄 이상이 되는 것은 허용한다. 새 본문 13px·제목 14px·설명 line-height 약 1.7, 섹션 padding 12px·간격 12px·기존 `--radius`를 사용한다. 신규 토큰·그래프·동작 애니메이션은 요구하지 않는다.

### 관계 0/1/N개와 데이터 순서

- `incoming`, `outgoing`, `related`는 각각 배열로 소비한다. 0개는 해당 구역에 “아직 준비된 연결이 없어요.” 또는 “아직 준비된 관련 기술이 없어요.”, 1개는 카드1개, N개는 같은 카드 N개를 세로로 반복한다. 1개만 추출하거나 첫4개로 임의 절단하지 않는다.
- 배열은 제공된 검토/출처 순서를 유지한다. 프론트에서 기술명 가나다순·성공 수·즐겨찾기로 임의 재정렬하지 않는다. 별도 우선순위 의미를 만들지 않는다.
- 방향 관계는 출발→도착을 보존한다. A→B를 근거 없이 B→A로 만들거나 관련 관계를 방향 관계로 전환하지 않는다. 원 출처의 추천 관계를 임의로 대칭화하지 않는다. 단일 방향 원본으로 incoming/outgoing을 파생할 때도 필터만 하며 방향을 뒤집지 않는다.
- 동일 대상을 가리켜도 출발 조건이나 근거가 다른 관계를 이름만 같다는 이유로 제거하지 않는다. key는 관계 식별자 또는 안정적인 출처 식별자+관계유형+위치 식별자를 사용한다. 관계 ID 정책은 백엔드 담당이 기존 데이터 구조와 함께 확정한다.
- 조건이 확인되지 않았으면 새 조건을 추정하지 않고 “연결 조건 미확인”으로 표시한다. 대상 기술과의 명시적 대응이 없으면 이름과 “연결할 기술 미확인”을 표시하는 비활성 행으로 남긴다. 클릭 가능한 것처럼 표시하거나 이름 검색 첫 결과로 이동하지 않는다.
- **시안의 기무라/니컷 이름 조건문 `Relations`는 합성 예시를 그리기 위한 코드다. 생산 코드에 복사하지 않는다.** 임의 기술명 상수·고정된 incoming/outgoing 한 쌍을 데이터 설계로 사용하지 않는다.

## 4. 상태·이동·초점·스크롤

- Context: 기존 `CacheContext`가 techniques/clips와 reload를 유지하고, `UIContext`가 기존 toast/loading을 담당한다. 새 화면 때문에 인증·캐시 구조를 교체하지 않는다.
- 부모 로컬 state: 검색·filter·page와 최초 연 기술 snapshot을 유지한다. 관계 이동은 부모 목록의 검색/페이지/scroll을 바꾸지 않는다.
- 모달 로컬 state: 표시 중인 `activeTechniqueId`, 이전 기술 ID stack, 설명 펼침 상태 및 설명/관계 읽기 상태. 실시간 기술 객체는 기존처럼 캐시에서 ID로 다시 찾아 최신 영상/집계를 보충한다. 이동에 기술명 일치를 사용하지 않는다.
- 관계 클릭: target ID가 현재 사용자의 기술로 명시적으로 연결되어 있을 때만 현재 ID를 이력에 push하고 해당 상세를 같은 Modal에서 표시한다. ID 미확인·삭제·접근불가라면 새 기술 생성/다른 이름 매칭 없이 안내하고 현재 상세를 유지한다.
- 이전: 한 단계 pop. 루트에서는 이전 버튼을 보이지 않는다. 같은 ID의 자기 관계를 눌렀다고 무한 이력을 쌓지 않는다. A→B→A 같은 실제 순환 탐색은 이전 버튼으로 한 단계씩 돌아갈 수 있어야 한다.
- 기술이 바뀌면 새 설명은 기본접힘, 모달 scroll은 상단, 대화상자 `aria-labelledby`는 새 기술명이다. 이동 완료 직후 기존 대화상자(tabIndex=-1)에 `focus({preventScroll:true})`해 새 맥락을 알린다. 사라진 관계/이전 버튼에서 BODY로 초점이 떨어져서는 안 된다.
- 최초 열기·닫기·Escape·native back·중첩 영상 모달의 포커스/트랩/복귀는 기존 `Modal` 및 modalStack 관리가 담당한다. 관계 이동용 effect는 ID 변경 시에만 실행하여 최초 마운트와 영상 모달 복귀를 가로채지 않는다. 새 Modal 인스턴스를 기술마다 key로 재생성하지 않는다.
- 조회 응답 경합: 기술을 빠르게 전환했을 때 이전 ID의 늦은 설명/관계/mastery 응답이 현재 ID를 덮어쓰지 않도록 cleanup/요청세대 식별을 사용한다. 성공 집계의 기존 alive cleanup 패턴을 유지한다.
- 설명 실패 재시도는 새 정보 읽기만 재시도한다. 전체 기술 캐시나 개인 메모를 빈값으로 덮지 않는다. 관련영상 수정/삭제 후 기존 `reloadClips`·`reloadTechniques` 및 snapshot 보완 흐름을 유지한다.

| 백엔드 모델/라우트/데이터 생성·이관 | Designer 결정 대상 아님. 현재 없는 필드/API와 안정적인 명시 대응·검토 상태 필요를 Leader/Claude에 전달. 운영 마이그레이션/반영은 별도 승인·절차 |

원본 `Layout`의 내비게이션, `Modal` 공용 초점 관리, `ClipDetailModal` 동작은 재사용한다. 시안의 fixture client·합성 인증·합성 ID940001대·검토 도구·remote-media stub·AST 번들 정규화는 생산에 이식하지 않는다. 원래 앱 미디어/인증 경로를 시안의 오프라인 경계로 바꾸지 않는다. 함께 작업 중인 타인의 미커밋 변경을 보존하고 관련 파일의 실제 diff를 대조한다.

## 6. 구현·검증 순서

1. 메인이 전달한 승인 v1·본 가이드·현재 task 범위와 Claude 실제 인수 상태를 확인한다. 고정 시안을 변경하지 않는다.
2. 기존 ID·이름·개인 기록을 보존하는 설명/관계 조회 데이터 경계를 Leader/Claude에서 정리한다. 기존 대응표의 `unreviewed` 항목을 확정 매핑으로 취급하지 않는다.
3. 기존 목록/Modal에 설명 섹션과 0/1/N 관계 목록을 연결한다. 설명과 note를 분리하고 기존 집계/관련영상 아래 흐름을 유지한다.
4. ID 기반 이동·이력·응답 경합 방지·초점 이동을 붙인다. 테스트에 고정 기무라/니컷만 쓰지 말고 다른 이름과 여러 관계 데이터를 사용해 상수 분기가 없음을 확인한다.
5. 정상·미준비·로딩·실패·재시도, 대상 미연결/삭제/권한제한, 다중 관계 순서·한 문장 조건을 확인한다. 기술/관계 조회 실패가 기존 사용자 기록을 지우지 않는지 확인한다.
6. 360/390/412px에서 가로 넘침 없음, 세로 스크롤 한 곳, 다중 세로카드 전체 도달, safe-area·단일 탭바, 긴 이름/조건·설명 줄바꿈을 확인한다.
7. 키보드 Tab/Enter/Space·자세히보기·관계이동/이전·Escape, 모달 안 activeElement 유지·새 제목 연결, 닫은 뒤 원래 목록 카드로 포커스 복귀, 검색/2페이지/스크롤 유지, 영상 상세→닫기→기술 상세 복귀를 실제 브라우저에서 검증한다.
8. 기존 성공 자동집계(표본없음 포함)·영상 사용합계·메모·영상 편집/삭제의 회귀를 검증하고 실제 Reviewer/QA 결과를 남긴다. 시안 CUA 성공을 생산 QA로 대체하지 않는다. 운영 DB 반영·배포 여부는 메인 절차에서 별도로 다룬다.

## 7. 주의사항·승인 범위

- “미매칭131개” 또는 이름 가설을 신규 기술131개로 바꾸지 않는다. 불확실 매칭 대상·관계 누락은 명시하며 이름 유사도만으로 기존 행에 붙이거나 기술을 자동 생성하지 않는다. 기존 `POST /api/techniques`의 생성 후 AI 분석 부작용을 대량 추가 경로로 무심코 실행하지 않는다.
- 전체 목록 포함 범위·포지션/일반 개념 분류·불확실 별칭 병합·조건 생성·검토 상태의 승격은 시안 화면 승인으로 자동 확정된 것이 아니다. 구현 중 실제 새 판단이 필요하면 Leader가 해당 항목을 구분해 다룬다.
- Android WebView는 웹 화면 변경 범위이며, 이 가이드는 `mobile/**`·권한·플러그인·아이콘·capacitor 설정 변경을 요구하지 않는다. 앱의 기존 native-top/safe-bottom을 이중 추가하지 않는다.
- 메인 task의 CUA 기록은 360/390/412px 시안과 관계 이동 포커스 보완 확인 근거다. 실제 production API 데이터·N관계·Android 실기기·전체159개 설명은 각각 별도 검증 사실로 남긴다.
- 사용자의 이번 명시 승인은 구현 착수와 승인 화면의 다중 카드 렌더링 요구다. 운영 DB 마이그레이션·실데이터 일괄 추가·배포를 완료했거나 별도 승인받았다고 기록하지 않는다.
