# 참고영상 기능·백데이터 수집 작업 절차서

- 작성일: 2026-11-09
- 상태: **사용자 요청으로 보류 — 절차서 작성만 완료**
- 관련 작업: [[task-054-improve-technique-tree]], [[IMP-0003-champion-data-review]]
- 재개 조건: 다른 작업 후 사용자가 실행 여부와 범위를 결정한다. 자동 재개일은 정하지 않는다.
- 사용자 지시: “해당 작업은 일단 보류로 해서 작업절차서만 일단 작성하고 다른 작업 후에 작업여부 결정하자”

## 1. 현재 기준과 이번 문서의 범위

기술트리 목록·관장 설명·전후/관련 기술 개선과 보류21개 확정 반영은 완료됐다. 마지막 확인한 기능 릴리스는 `20261109-000243-78d3ac9c`, 문서 릴리스는 `20261109-000550-0aef8e11`이다. 당시 총 기술172개·참고 연결131개·개인 영상177개를 확인했다. 이 수치는 과거 검증 기준이며 재개 시 현재 상태를 다시 확인한다.

새 제안명은 **참고영상**이다. 공통 영상 추천 영역·수집기·신규 테이블은 미구현이다. 이번에는 절차서와 보류 기록만 작성한다. 수집 실행·API 키 설정·DB 변경·화면 구현·커밋/push·배포·예약 작업은 시작하지 않는다.

기존 기술트리용 승인 시안 v1과 과거 DB/배포 승인은 새 참고영상 기능의 실행 승인으로 확대하지 않는다. 재개 후 사용자가 명확히 승인한 범위는 반복해서 묻지 않고 수행한다.

## 2. 재개 시 먼저 정할 항목

| 항목 | 현재 제안 | 재개 시 결정 |
|---|---|---|
| 초기 대상 | 대표10개 기술·기술당2~3개 영상 연결 | 대상 기술과 규모. 아직 확정 아님 |
| 수집 경로 | 참고사이트 공개 영상 링크 → 부족한 기술의 공식 YouTube 검색 → 직접 URL 추가 | 허용 출처·자동 검색 범위 |
| 영상 종류 | 강의/경기/드릴 | 최초 제공 종류·도복/노기 표시 범위 |
| 검토·공개 | 후보는 draft, 근거 검토 후 approved 공개 | 검토 담당과 공개 방식 |
| 운영 범위 | 신규2테이블·기존 개인영상 재사용 | 구현·운영 반영·배포 범위 |
| 갱신 | API 데이터30일 이내 갱신/삭제, 신규 후보 수집 주기는 미정 | 실행 주기·한도·실패 알림 방식 |

재개 시 최신 AGENTS·프로젝트 절차·현재 코드/DB 스키마·배포 상태를 확인한다. 현재 checkout의 다른 작업과 미커밋 변경을 보존하고 이 기능의 변경만 분리한다. YouTube API 연결 및 할당량은 비밀 값을 노출하지 않고 확인한다.

## 3. 설계·시안 준비

기존 기술 상세 모달을 바탕으로 ‘참고영상’ 카드와 빈 목록·로딩·실패·재생 불가 상태를 준비한다. 카드 정보는 썸네일·제목·채널/강사·유형·확인 구간·짧은 설명을 제안한다. 동작은 ‘해당 구간 보기’, ‘원본 보기’, ‘내 참고영상에 저장’이다.

기존 VideoPlayer 재사용을 검토한다. ClipDetailModal은 개인 영상 ID로 활용 기록을 쓰므로 공통 영상 ID를 그대로 전달하지 않는다. 공통 영상 열람은 개인 기록을 쓰지 않는 경로로 구성하고, 사용자가 저장한 이후 기존 개인 상세·메모·활용 기록에 연결한다. 새 UI의 구체적 구성은 당시 프로젝트 절차와 사용자 결정에 따른다.

## 4. 백데이터 설계안

| 구성 | 주요 값·제약 |
|---|---|
| `reference_videos` | 플랫폼·영상ID·원본URL·제목·채널·썸네일·길이·재생상태·메타정보 확인시각. 플랫폼+영상ID 고유키 |
| `technique_reference_videos` | 공개 기술키·영상ID·강의/경기/드릴·확인 구간·자체 설명·발견 출처/방법·검토상태/담당/시각·정렬순서. 초기 기술↔영상 쌍 중복 방지 |
| 기존 `video_clips`와 활용 기록 | 개인 저장·편집·메모·활용 기록을 그대로 사용. 공통 목록으로 자동 전환하지 않음 |

공통 기술키는 현재 catalog의 안정적인 slug를 사용하고 등록 시 유효성을 검사한다. JSON catalog를 SQL 외래키 대상으로 가정하지 않는다. 개인 기술은 기존 사용자별 대응 결과로 찾으며 공통 영상에 특정 사용자의 기술 ID를 저장하지 않는다. 같은 개인 기술에 대응하는 유효 공개 slug가 여러 개면 영상ID로 합쳐 중복 제거한다.

선수명은 선택 메타정보로 두고 선수·우승 이력 테이블은 초기 구성에 넣지 않는다. 다중 확인 구간이나 인물별 검색이 필요해지면 별도 확장 여부를 결정한다.

## 5. 후보 수집·정리

1. 승인된 대상 기술과 수집 출처를 목록으로 고정한다.
2. 참고사이트의 대상 상세 페이지에서 공개 영상URL과 출처 페이지를 수집한다. 화면의 선수별 영상 수를 사용/성공 횟수로 가져오지 않는다.
3. 부족한 기술은 한글·영문명·확인된 별칭으로 공식 YouTube 검색 API를 사용한다. 직접 입력URL도 같은 후보 처리 흐름에 넣는다.
4. 플랫폼·영상ID를 정규화하고 URL 변형 중복을 제거한다. 한 영상에 여러 기술 연결을 허용한다.
5. 공식 영상 조회 API로 제목·채널·썸네일·길이·공개/임베드 상태를 확인한다. 출처·검색어·수집시각·실패 사유를 기록한다.
6. 후보 목록을 검토 가능한 파일/화면으로 먼저 준비한다. 검색량·중복 제거량·확인 불가량·기술별 후보 수를 집계한다. 실제 수집 전 영상 건수를 추정치로 확정하지 않는다.

검색은 할당량 안에서 분산하고 재시도 시 중복을 만들지 않게 한다. 일시적인 API 실패를 삭제/비공개로 단정하지 않는다. 현재 개인영상 등록 API는 개인 행 생성과 자동 분석을 실행하므로 공통 후보 수집기가 그 경로를 일괄 호출하지 않도록 분리한다. 초기 수집 대상은 링크와 메타정보다.

## 6. 기술·구간·관장 설명 검토

후보는 draft로 시작한다. 기술 대응·영상 유형·확인 가능한 도복/노기·구간을 검토하고, 확보한 근거를 관장 에이전트에 전달해 설명과 연결의 정확성을 검토한다. 제목이나 선수명만으로 실제 기술 사용·성공·확인 구간을 확정하지 않는다. 근거가 부족한 후보는 대기 또는 제외 사유를 남긴다.

검토를 통과한 연결만 approved로 공개한다. 설명은 자체 작성하고 출처URL·검토 담당·시각을 남긴다. 영상 수는 중복 제거된 영상 건수로 표시하며 성공률·사용 횟수·선수 순위로 전환하지 않는다.

## 7. 구현·독립 검증

수집·검토·조회와 개인 저장 흐름을 분리해서 구현한다. 개인 저장은 사용자 선택으로만 실행하고 연타/재시도 시 중복 등록을 방지한다.

검증 대상은 영상 중복·다중 기술 연결·이름 변경 뒤 기술 대응·검토 전 자료 미노출·다른 계정의 개인 자료 접근 차단·공통 열람에서 개인 활용 기록 미생성·저장 후 개인 흐름 연결·API 실패/재시도·재생 불가 상태다. 실제 앱 화면도 대표 모바일 폭에서 확인한다. Reviewer 감사 후 QA를 수행하고 결함 수정 시 해당 변경을 재검토한다. 실데이터·실기기 확인과 합성 검증은 구분해 기록한다.

## 8. 승인된 운영 반영·배포

구현·검증이 끝나면 실제 대상 기술·고유 영상·기술 연결 수, 신규 스키마, 개인 데이터 영향, 백업·복원 방법을 검토 가능한 형태로 제시한다. 운영 실행은 사용자가 승인한 구체적 범위 안에서만 진행한다.

반영 전 현재 상태와 백업을 보관하고 dry-run으로 추가/유지/제외/충돌을 확인한다. 보안 정보·개인 원자료·원시 백업은 Git에 포함하지 않는다. 반영은 중복 방지·트랜잭션·사후 대조를 갖춘 도구로 수행하고 개인 메모·활용 기록을 보존한다.

복원은 이번 변경으로 만든 행과 상태가 그대로인 항목에 한정한다. 이후 사용자가 저장·편집·활용한 자료를 자동 삭제하지 않는다. 필요한 경우 노출 중지/코드 복원과 데이터 보존을 우선 검토한다.

선택 변경만 커밋/push하고 당시 공식 배포 절차를 따른다. webhook 자동 배포와 수동 배포를 중복 실행하지 않는다. RELEASE_RESULT·실행 버전·health·정적 자산·실제 조회/저장·소유 격리를 확인하고 작업 이력과 ACTIVE.md를 함께 갱신한다. 승인·배포·운영 검증·사용자 실기기 확인을 별도 사실로 기록한다.

## 9. 운영 중 갱신

API 메타정보와 자체 편집 설명/검토 이력을 구분한다. 재개 시 확인한 공식 정책에 맞춰 저장 API 데이터를 갱신/삭제하고, 삭제·비공개·임베드 제한은 노출 상태에 반영한다. 후보 추가 주기와 자동 실행은 사용자 결정 후 설정한다. 이번 보류 중에는 수집·갱신 작업을 예약하지 않는다.

## 10. 현재 인계 상태

**절차서 작성 완료 / 참고영상 추가 개발·수집 보류 / 재개 여부는 다른 작업 후 사용자 결정.**

기존 기술트리 개선과 운영 반영은 완료 상태를 유지한다. 초기10개·각2~3개는 제안일 뿐 승인된 수집 목표가 아니다. 본 문서는 구현·API 설정·수집 실행·운영 DB 변경·배포를 수행한 결과물이 아니다.
