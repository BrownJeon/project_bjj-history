## 1. 레이아웃 설계와 보존 기준

목표는 기존 홈에서 최근 피드백 3개의 진행 상태를 보고, 전체 목록을 검색하거나 피드백을 보완하고 연습 결과를 관리하는 것이다.

기존 `Layout`, `MasterBar`, `HomePage`, `WeeklyTaskCard`, 하단 내비게이션, `Modal`을 유지한다. 데모의 복사된 DOM·합성 데이터·native dialog·인라인 스크립트를 제품 코드에 옮기지 않는다. 실제 React 컴포넌트를 확장한다.

홈 순서는 기존과 동일하다.

1. 관장 바.
2. “오늘도 매트 위에서 / 훈련 기록”과 프로필 아이콘.
3. 최근 관장 대화 또는 첫 대화 안내.
4. 오늘 훈련 기록 카드.
5. 피드백 추가 카드와 최근 피드백.
6. 이번 주 과제.
7. 이번 주 요일 스트립.
8. 이번 달·총 수업·기술 수 통계.
9. 이번 주 어드바이스.
10. 기존 5탭 SVG 내비게이션.

기존 `.app-shell`의 최대 460px, `.app-content`의 `padding: 0 20px 80px`, 하단 내비게이션 62px, 관장 바의 위치·54px 높이·검색 pill, 원래 글꼴·색·여백·버튼 스타일을 유지한다. 새 폰 목업·상태바·홈 재배치·새 전역 팔레트를 추가하지 않는다.

피드백은 기존 `FeedbackProvider`의 단일 상태와 `FeedbackPanel`의 `Modal fullScreen`을 그대로 사용한다. 실제 전체 화면 모달은 `--surface-up` 배경, 최대 460px, 기존 padding과 제목·우측 SVG 닫기 버튼을 사용하며 하단 내비게이션을 덮는다. 대표 폭은 390px, 경계는 360·412px다. 추가 조작은 이름이 있는 버튼·체크박스·입력 요소로 제공하고, 상태는 색과 함께 텍스트로 표시한다.

## 2. 홈 최근 피드백과 상태 표시

기존 `FeedbackHomeCard`의 `listFeedback({ limit: 3 })`를 보존한다. 날짜 내림차순, 같은 날짜는 ID 내림차순의 최근 3개를 보여준다. 기존 “피드백 추가” 카드와 카드 스타일은 유지한다.

“최근 피드백” 제목 우측에 “전체 보기 ›” 버튼을 둔다. 빈 목록·오류 상태에서도 전체 목록 진입 경로를 제공한다. 카드 전체를 누르면 기존 `openFeedback(id)`로 상세·보완 모달을 연다.

정리 상태와 훈련 상태는 서로 다른 의미다.

| 구분 | 표시 | 기준 |
|---|---|---|
| 정리 상태 | 정리됨 | summary가 있고 summaryStale이 false |
| 정리 상태 | 이전 내용 기준 | summary가 있고 summaryStale이 true |
| 정리 상태 | 보완 중 | summary가 없음 |
| 훈련 상태 | 훈련완료 | 저장 결과 중 `outcome: done`이 하나라도 있음 |
| 훈련 상태 | 훈련중 | done은 없고 결과가 하나 이상 있음 |
| 훈련 상태 | 과제중 | 결과가 없고 실제 현재 열린 과제와 피드백의 taskBinding이 일치 |
| 훈련 상태 | 표시 없음 | 위 조건에 해당하지 않음 |

서버의 `trainingStatus: completed / training / assigned / null`을 위 문구로 표시한다. `taskBinding`이 있다는 사실만으로 과제중으로 표시하지 않는다. 과제가 교체·마감되었거나 결과가 수정·삭제되면 현재 상태를 다시 반영한다. 여러 결과 중 최근 결과가 실패여도 과거의 done이 남아 있으면 훈련완료다.

결과 추가·수정·삭제 뒤 훈련 상태는 바로 반영한다. 기존 summary가 stale이 되면 정리 상태는 “이전 내용 기준”과 다시 정리 안내로 바뀐다. 최신 정리가 필요하다는 기존 과제 지정 보호 조건을 유지한다.

## 3. 전체 피드백 목록

진입은 홈 제목 우측 “전체 보기”다. 실제 페이지는 기존 `Layout` 아래에서 공통 관장 바와 하단 메뉴를 사용한다. 화면 제목은 “피드백”, 우측에 “+ 추가”를 배치한다. 새 하단 탭은 추가하지 않는다.

기본 구성은 `ClipsPage`의 다음 순서와 컴포넌트 관례를 사용한다.

1. 제목과 추가 버튼.
2. “제목·기술명·내용 검색” 검색창.
3. 전체 / 최신순 / 즐겨찾기 / 완료 필터 칩.
4. 검색 가능한 기술 선택 드롭다운과 선택 조건 해제.
5. 조회 수와 피드백 카드 목록.
6. 기존 `Pagination` 방식의 페이지 이동. 기본 10개씩.

기본은 전체이며 전체와 최신순은 날짜 DESC, ID DESC의 안정 정렬을 사용한다. 즐겨찾기는 `starred: true`, 완료는 훈련완료에 해당하는 피드백이다. 검색·선택 필터·기술 조건을 함께 적용하고, 적용된 결과의 total로 페이지를 계산한다. 조건을 바꾸면 첫 페이지로 간다. 검색 범위는 승인 데모의 제목·기술명·원문·정리 개요다.

기술 조건에는 피드백에 저장된 기술명을 사용한다. 현재 기술트리에서 삭제·변경된 과거 기술명도 해당 피드백을 조회할 수 있어야 한다. 기술 이름을 선택하거나 해제해도 검색어와 다른 필터를 임의로 지우지 않는다.

카드는 날짜, 정리 상태·훈련 상태, 제목, 기술·상황, 내용 요약을 표시한다. 제목은 기존 규칙인 summary.title → technique → “피드백”을 따른다. 즐겨찾기 버튼은 상세를 여는 카드 버튼과 별개 조작이며, 누를 때 상세 열림이 같이 실행되지 않는다. 별 모양과 접근 가능한 이름·선택 상태를 함께 제공한다.

목록의 불러오는 중/피드백 없음/조건 결과 없음/조회 오류·재시도를 구분한다. 오류를 빈 목록으로 바꾸지 않고 저장 실패를 성공처럼 표시하지 않는다. 즐겨찾기를 변경하거나 결과를 저장한 뒤 목록·홈·복기에 최신 데이터가 반영되어야 한다.

## 4. 입력 화면의 기술·상황 선택

기존 `FeedbackPanel`의 입력 순서인 날짜 → 상황 → 기술 → 원문 → 접힌 영상 연결 → 임시저장/관장과 보완하기를 유지한다. 날짜와 원문의 기존 필수 조건을 유지하고, 상황·기술을 새 필수 항목으로 바꾸지 않는다. 포지션 입력은 추가하지 않는다.

### 기술

- `CacheContext`의 등록 기술을 검색해 1개 선택한다. 참고영상 등록의 `TagPicker`가 가진 등록 suggestions 제한과 같은 원칙을 적용한다.
- 승인 v2처럼 검색·선택·선택 변경·해제를 제공한다. 입력한 검색어 자체를 새 기술로 등록하거나 자유 기술명으로 저장하지 않는다.
- 현재 피드백의 단일 기술 값 계약을 유지한다. 다중 기술 기능으로 확장하지 않는다.
- 기존 미등록 기술명은 그대로 표시·보존한다. 사용자가 실제로 선택을 바꾸기 전에는 기존 값을 지우거나 다른 기술로 추정 매칭하지 않는다.
- 기술 목록 조회 실패는 등록 기술 0개와 구분하고, 이미 선택하거나 기존에 저장한 이름을 보존한다.

### 상황

- 수업 / 스파링 / 영상 복기 / 개인 연습 / 기술토론 / 기타를 체크 항목으로 제공하며 복수 선택할 수 있다.
- 일반 상황 텍스트 입력창은 없애고 기타를 체크했을 때만 기타 상황 입력창을 표시한다.
- 체크와 기타 내용도 저장·재개·충돌 처리 대상이다. 기술 선택 창을 열고 닫거나 관장 단계로 이동해도 유지한다.
- 과거 자유 상황 문장은 구분자나 단어 포함 여부로 임의 분해·재분류하지 않는다. 기존 원문은 기타 내용으로 보존하고, 사용자가 변경하지 않은 경우 원래 situation을 불필요하게 patch하지 않는다.
- 복수 체크 상태를 정확히 복원할 영속 표현과 기존 문자열의 호환은 §8의 미확정 계약 항목을 먼저 확정해야 한다.

기존 `FeedbackClipPicker`의 조회 필터·기술 조건·5개 페이징·조건 밖 선택 보존과 기존 `ClipDetailModal`을 사용한다. 데모의 축약된 영상 선택기를 제품의 기존 선택기 대신 만들지 않는다.

## 5. 닫기와 보완 대화 보존

기존 앱의 닫기는 `FeedbackContext.requestClose` → `controller.close()`이며 navigate를 호출하지 않는다. 이 정상 동작을 유지한다. 홈·수업·전체 목록 중 어디서 열었든 모달만 닫는다.

전체 목록을 피드백 모달 뒤에서 유지하여 검색·필터·기술 조건·페이지·스크롤이 보존되게 한다. 닫기에서 홈 이동·새 목록 초기화·페이지 remount를 추가하지 않는다. 데이터 변경으로 현재 페이지가 사라진 경우에만 기존 페이지 유효 범위 처리와 합의된 서버 계약을 적용한다.

미저장 입력·보완 답변·충돌·저장 여부 불확실 상태에서의 닫기 확인, 저장하고 닫기, 로컬 변경 폐기, 계속 편집을 기존 controller와 Modal 경로로 유지한다. X·Escape·기존 Android 뒤로가기에서 동일한 보호를 적용한다. 닫힌 뒤에는 모달을 열었던 버튼으로 초점을 돌린다.

질문은 기존처럼 하나씩 이어가고 이전 질문으로 돌아갈 수 있다. 저장된 원문·확정 답변·미제출 초안·현재 질문 위치·변경 전 이력의 구분을 보존한다. 저장하고 닫은 뒤 같은 피드백을 열면 새 피드백을 중복 생성하지 않고 이어간다. 관장 통합 정리는 원문과 확정 보완 답변을 포함하며 미제출 초안을 근거로 확정하지 않는다.

## 6. 연습 결과 수정·삭제

`FeedbackSummary`의 기존 `PracticeResults` 영역과 등록 폼을 확장한다. 날짜, 결과, 연습 상황, 관찰한 점의 필드·라벨을 등록과 수정에서 공통으로 사용한다.

| 저장 값 | 표시 |
|---|---|
| not_tried | 시도 못 함 |
| tried_failed | 해봤는데 안 됨 |
| done | 됐음 |

각 저장 내역 우측에 수정 / 삭제 버튼을 둔다. 수정은 해당 내역 안에 기존 값이 채워진 폼을 펼치고, 취소 / 수정 내용 저장을 제공한다. 하나를 수정하는 동안 새 결과 등록 폼과 구분한다. 취소는 서버 기록을 바꾸지 않는다. 저장 실패·409에서는 입력을 보존하고 서버 상태 확인 경로를 제공한다.

삭제는 대상 날짜·결과와 삭제 후 복구할 수 없음을 확인한 뒤 실행한다. 취소·실패에서는 기록을 유지한다. 성공 시 해당 결과만 제거하고 나머지 결과·원문·대화·영상·요약은 보존한다. 마지막 done을 수정하거나 삭제하면 남은 결과와 실제 현재 과제에 따라 훈련중/과제중/상태 없음으로 재계산한다.

두 작업 모두 현재 Feedback revision과 결과의 실제 ID를 사용한다. 수정은 결과 ID/createdAt을 보존하고, 삭제는 해당 ID만 제거한다. 최신 DTO를 controller가 수용해 상세·홈·목록·기간별 복기에서 일관된 결과를 보여주게 한다. 기존 AI pending 무효화·summaryStale과 이전 카드 보존 계약을 유지한다. 숙련도를 자동으로 올리지 않는다.

| `web/src/contexts/FeedbackContext.jsx` | 기존 단일 상태·stage/close 흐름 유지, 즐겨찾기를 포함한 갱신 인계 |
| `web/src/api/feedback.js` | 확정된 목록 조건·즐겨찾기 set·결과 PATCH/DELETE 클라이언트 함수 |
| `web/src/styles/feedback.css` | 새 선택 컨트롤·배지·목록·편집에 필요한 범위의 스타일 |
| `HomePage`/`Layout`/`Modal`/`ClipsPage`/`ClassEditPage` | 기존 구조·스타일·동작 보존. 새 홈 셸이나 별도 수업 폼을 만들지 않음 |

신규 컴포넌트 분해·이름은 확정된 실행 주체가 사용자 승인 범위와 현재 정책에 맞게 인계받아 결정한다. 이 표는 파일별 변경 허가나 추가 범위의 자동 승인이 아니다.

### 준비된 서버 계약과 UI 연결

| 엔드포인트 | 요청/사용 필드 | UI 처리 |
|---|---|---|
| GET `/feedback` | `page`, `limit`, `filter`, `technique`, 검색 키는 §8 확인. 응답 `items/total/page/limit` | 홈 limit3, 전체 기본10, 필터 적용 후 total, 요청 경합에서 최신 조건 결과 유지 |
| GET `/feedback/:id` | 기존 DTO + `starred`, `trainingStatus` | 기존 open/resume 및 상세 상태 표시 |
| PUT `/feedback/:id/star` | `{starred:boolean}` → `{id,starred}` | 멱등 set, 실패 시 유지/복구. 본문 revision·AI hash/token과 독립 |
| PATCH `/feedback/:id/results/:resultId` | `{revision,date,outcome,context,note}` | 해당 결과 수정, 성공 DTO 반영, 실패 입력 보존 |
| DELETE `/feedback/:id/results/:resultId` | `{revision}` | 확인 후 해당 결과 삭제, 성공 DTO 반영 |
| 기존 POST/PATCH `/feedback`, `/:id` | 기술 선택·상황 체크 영속 필드는 §8 확인 | 기존 원문/날짜/영상/대화 호환 유지 |
| 기존 `/:id/answer`, `/:id/ask`, `/:id/summarize`, `/:id/task`, `/:id/results`, `/recap` | 기존 계약 유지 | 한 질문씩 보완·통합 정리·과제 지정·신규 결과·기간별 복기 유지 |

성공 응답은 기존 `{success,data,message}`와 axios 언래핑을 유지한다. 다른 사용자/없는 결과404, 잘못된 값400, 낡은 revision409 및 저장소 준비 안 됨503을 실제 오류로 처리한다. 즐겨찾기 응답과 다른 DTO가 경합해 별이 되돌아가지 않도록 기존 목록/상세 갱신 경로에 인계한다.

별도 `starred` 컬럼을 추가하는 명시 스키마 계획은 Leader/backend 준비 기록의 선택을 따른다. 이 가이드는 운영 스키마 적용·마이그레이션 실행·push·배포 승인을 포함하지 않는다.

### 구현 인계 순서

1. Leader가 현재 실행 주체와 §8의 실제 전송 계약을 확정해 양쪽 담당에게 전달한다. 이미 승인된 화면은 다시 승인받지 않는다.
2. Backend 담당은 확정한 목록/DTO·즐겨찾기 set·결과 수정/삭제와 기존 데이터 보존 계약을 준비하고, schema 적용 범위를 별도 운영 승인과 구분한다.
3. Frontend 담당은 기존 API/controller 연결을 확장한 뒤 홈 상태·전체 목록·선택 입력·결과 편집을 승인 v2에 맞춰 반영한다. 기존 오버레이 닫기·대화·영상 흐름을 유지한다.
4. 기존 팀 절차대로 독립 Reviewer → QA에 실제 변경 파일과 검증 범위를 인계한다. 새 검증 수단이나 실행 환경의 선택이 필요하면 현재 사용자 사전승인 정책을 따른다.
5. 최종 사용자 확인과 운영 적용·배포 단계는 Leader가 확정한 현재 담당·승인 범위로 인계하며 자동 실행하지 않는다.

## 8. 확정되지 않은 구현 계약

아래 사항은 승인된 화면의 기능 범위를 바꾸는 제안이 아니라, 현재 task 기록에서 실제 전송 계약을 특정할 수 없는 항목이다. 이 문서에서 임의로 확정하지 않는다.

| 항목 | 확인한 기록 | 인계할 확인 사항 |
|---|---|---|
| 목록 검색 파라미터 | Leader 준비안 `search`, backend 준비안 `q` | 프론트·서버에 사용할 하나의 이름 |
| 신규 목록 경로·파일명 | 목록 신설은 승인됨. 실제 React 경로·파일명 미기재 | 기존 Layout 아래의 경로와 파일 소유 범위 |
| 상황 복수 체크 영속 표현 | 기존 situation TEXT 보존, 구조화 메타데이터는 준비안에서 대안으로 제시 | 신규 체크/기타 값의 왕복 저장 형식과 과거 문자열 untouched 처리 |
| 선택 기술 전송 키 | 등록 Technique 소유권 확인→기술명 snapshot 저장 준비안. 요청 키 미기재 | 선택 ID와 기존 명칭의 요청/응답 필드 및 명시 해제 표현 |

현재 실행 주체·실행 도구 선택은 Leader가 별도로 사용자에게 확인 중인 사항이다. 디자이너는 이를 대리 확정하지 않는다. 이미 사용자에게 승인받은 v2 화면·상태·닫기 동작의 재승인은 요청하지 않는다.

## 9. 인수 후 확인 항목과 검증 경계

후속 Reviewer/QA 인계에서는 다음 사용자 동작과 보존 조건을 기준으로 확인한다. 이 문서를 작성하며 앱 테스트·운영 DB 검증·배포를 실행한 것은 아니다.

- 홈 기존 구성·스타일과 최근 3개, 정리 상태와 훈련 상태의 동시 표시.
- done 여러 개, 마지막 done 수정/삭제, 시도 못 함/실패만 존재, 실제 과제 교체·마감의 상태 변화.
- 전체 목록 검색·각 필터·기술 조건 조합, 10개 페이징, 즐겨찾기 저장·재조회·응답 경합.
- 홈·수업·전체 목록 진입 후 X/Escape/뒤로가기의 이전 화면·검색·조건·페이지·스크롤·초점 보존.
- 미저장 확인의 저장/폐기/계속 편집, 보완 답변·초안·질문 위치의 저장 후 재개, 기존 ID 중복 생성 방지.
- 등록 기술 검색/선택/해제, 상황 복수 체크·기타 입력, 기술 선택 후 상황 유지, 과거 기술/상황 원문 보존.
- 결과 수정의 같은 폼·prefill·취소·실패 입력 보존·409, 삭제 취소/실패 보존과 단일 결과만 삭제.
- 결과 날짜 변경에 따른 기간별 복기 집계, summaryStale/이전 카드 보존/다시 정리 및 stale 과제 지정 차단.
- 기존 등록영상 5개 페이징·선택 보존·ClipDetailModal, 수업 캘린더·수업 추가 원래 폼, 단일 질문 보완 흐름.
- 실제 360/390/412px에서 가로 넘침·터치·포커스·모달 스크롤 확인. 기존 데모/정적·합성 확인을 실제 앱/API/DB 검증으로 대체하지 않음.

화면·백엔드 변경 범위로 네이티브 설정이나 APK 변경은 포함하지 않는다. 운영 적용·최종 검증·배포는 확정된 실행 담당과 기존 절차에 별도 인계한다.
