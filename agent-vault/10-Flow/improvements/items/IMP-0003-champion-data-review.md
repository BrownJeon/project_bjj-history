## 현상

현재 기술 모델·기술 API에는 선수·경기·챔피언 관련 필드가 없다. 참고사이트는 기술 상세에 선수별 경기 영상 수와 대표 영상 링크를 표시한다.

## 기대하는 모습

사용자 원문:
> 3. 상세화면의 기술상세화면에서 ' 기술을 쓰는 챔피언'도 좋은 아이디어같은데 이건 기존에 구현되어 있는게 없어서 백데이터를 어떻게 구성하면 좋을지에 대하여 리버스엔지니어링해서 검토해줘.

## 근거

- 2026-11-08 사용자 요청. 이번 3번은 구조·구성 방법의 검토이며 실제 챔피언 기능 구현 승인이 아니다.
- 참고: https://labs.quartz.best/ko-KR/pbb/techniques/kimura
- 공개 페이지의 이름·국가·경기 영상 수·대표 YouTube 링크 및 추가 선수 안내를 직접 확인했다. 비공개 DB 스키마·선정 기준·앱 내부 전체 데이터는 미확인이다.

## 분류 메모 (착수 때 Leader)

- 선수·기술·경기 근거를 구분하는 구조와 간단한 수동 관리 구조를 비교한다. 실제 내부 구조를 알아낸 것처럼 보고하지 않는다.
- 경기 사용·승리·챔피언 타이틀·강의 제작은 각각 다른 근거다. 이름만으로 대표 기술이나 챔피언 자격을 확정하지 않는다.

## 영상 수집 계획 제안 (2026-11-09, 미실행)

1. 초기 후보: 참고사이트의 공통159개 기술 상세에 공개된 영상 URL과 출처 페이지를 모은다. 선수명·영상 수는 출처 주장으로 보관하고 경기 사용/성공 검증으로 취급하지 않는다. 실제 영상 후보 수는 전체 링크 추출·중복 제거 후 산정한다.
2. 부족한 기술 보완: 한글/영문명·확인된 별칭으로 YouTube Data API search.list 검색을 제안한다. 공식 강사/선수·대회 주최 채널을 우선 검토하고 임베드 가능 후보를 찾는다. 사용자가 직접 제출한 URL도 같은 후보 흐름에 넣는다.
3. 메타정보: videos.list로 영상 ID별 제목·채널·썸네일·길이·공개/임베드 상태를 조회한다. 플랫폼+영상ID로 중복 제거하고 원본URL·발견출처·검색어·수집시각을 기록한다. 검색은 할당량 안에서 큐로 분산하고 조회 실패/일시적 오류는 확인불가 상태로 재시도한다.
4. 연결 검토: 공통 기술 키로 후보를 연결하고 애매한 대응은 draft로 둔다. 강의/경기/드릴 유형, 도복/노기(확인된 경우), 실제 확인 구간, 기술별 설명을 검토한다. 관장 에이전트는 확보한 근거 자료를 바탕으로 설명을 검토하며 제목만으로 사용/성공·구간을 확정하지 않는다. 영상 구간 근거를 확보하지 못한 후보는 검토 대기로 둔다.
5. 공개·유지: 승인된 연결만 노출한다. API에서 수집한 메타정보는30일이내 갱신/삭제하고 재생 불가 상태를 반영한다. 일시적 API 실패를 영상 삭제로 단정하지 않는다. 공통 영상 원본 다운로드·개인영상 등록 API의 자동분석을 일괄 실행하는 수집안은 사용하지 않고 링크·메타정보 중심으로 제안한다.

초기 범위는 대표10개 기술에 각2~3개 영상 연결을 검토해 품질과 작업량을 확인한 뒤 전체로 확장하는 안을 제안한다. 이 범위·주기·YouTube API 설정은 아직 사용자 확정/구현이 아니다. 기존 개인영상·메모는 공통 자료로 자동 전환하지 않는다.

현재 코드에는 사용자 URL 등록 후 썸네일·영상 분석 흐름과 검색결과 URL 생성은 있지만, 기술별 공식 YouTube 검색·공통 영상 수집기는 확인되지 않았다. 기존 POST /api/clips는 개인행 생성과 자동분석을 실행하므로 공통 후보 수집과 분리해야 한다.
