# task-046 — 스파링 기술 선택기 (1단계: 데모)

## 사용자 요청 (2026-09-22)

> 스파링 화면에서 성공한 기술·실패한 기술 목록도 기본 체계의 기술만 정의하고 그 외에는 직접 입력하는 방식으로. 기본 기술은 관장 에이전트가 정의하고 검토 후 확정.

관장이 기본 칩 20개를 제안 → 사용자가 검토 중 **방향 전환**:
> 목록이 많아지면 화면 공간이 커진다. 처음엔 서브미션·패스·탈출·스윕 등 **큰 카테고리**를 고르고, 카테고리에 따라 **내가 등록한 기술**을 셀렉트박스·검색창으로 선택. 없으면 `+` 로 직접 추가. 카테고리는 관장과 함께 정하고, **데모 화면을 직접 보고 결정**.

사용자 결정:
1. `+` 추가 시 **"이 기록에만 / 기술트리에도 등록"을 매번 고른다.**
2. 데모는 **앱 안 데모 화면**(메뉴 밖 주소, 저장 안 함, 배포).
3. RNC 표기는 정본 `리어네이키드 초크`.

**이번 범위 = 1단계(데모 구현·배포)만.** 실제 스파링 화면 교체·기술트리 category 반영은 사용자가 데모를 본 뒤 2단계로.

## 관장 UX 권고 (데모에 반영)

- 휴대폰 기본 셀렉트박스(휠·팝업)보다 **검색창 + 탭 목록**. 카테고리당 많아야 14개.
- 목록 순서 = **이 훈련생 사용 횟수(성공+실패 합산)순**, 위 5~6개 + '더 보기'.
- 검색은 **띄어쓰기 무시**(`techMatch.normalize` 규칙), **고른 카테고리 밖까지** 찾고 다른 카테고리 결과엔 카테고리명 표시. `+` 는 이름이 똑같은 기술이 없을 때만.
- 성공·실패는 **같은 선택기**. 공간이 아까우면 선택기 하나 + 고른 뒤 [성공][실패].
- 한 라운드 안에서 마지막 카테고리 유지. 고른 기술은 카테고리 줄 아래 칩 한 줄.
- `+`: 비슷한 이름이 있으면 "이거예요?" **묻기만**(자동으로 붙이지 않음). **보류 4종은 트리 등록 금지 → "이 기록에만"**(등록되면 보류가 저절로 결정됨). 관장은 "기술트리에도 추가" 기본 켜짐을 권고 — 사용자 결정은 "매번 고르기".
- 미분류 기술은 검색으로만 보이고 '미분류' 표시 — 분류 안 했다고 못 고르는 일 없게.
- (범위 밖) 가드 이름을 빼면 "어느 자리에서"를 적을 곳이 메모뿐 — `spar_sessions.positions` 편집 화면 부재.

  1. 카테고리 줄(6개), 라운드 안 마지막 선택 유지.
  2. 선택 영역: 검색창 + 사용 횟수순 목록 5~6개 + '더 보기'. 검색은 전 카테고리, 다른 카테고리 결과엔 이름표. 똑같은 이름이 없으면 `+ "입력값" 추가`.

  4. 고른 기술 칩 한 줄(성공/실패 색 구분, × 해제). 실패 원인 태그는 "지금 화면과 같음" 안내만.
  5. 비교 스위치 2개: 목록 방식 `검색 + 탭 목록` ↔ `셀렉트박스 + 검색` / 배치 `성공·실패 선택기 따로` ↔ `선택기 하나 + [성공][실패]`.
  6. 분류안 검토 표(접힘): 카테고리별 · 제외(포지션/기타) · 미정 4 · 관장 확인거리.
- 원칙: `SparEditPage.jsx`·백엔드·DB·기존 기록 **무변경**. 정규화 함수는 서버 `normalize` 와 같은 규칙(NFC·소문자·공백·`-·ㆍ・` 제거)을 데모 파일에 작게.
